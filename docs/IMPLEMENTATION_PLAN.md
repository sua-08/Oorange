# Orange Task Farm — Implementation plan

- Updated: 2026-09-08
- Current state: 기획 완료, 코드 구현 전

## 1. 전달 전략

가장 작은 수직 흐름부터 만든다.

```text
기반 규칙
→ 유한 목표 분석
→ 3분 행동과 시작
→ 로컬 저장과 동결
→ 진행률과 재방문
→ MVP-0 검증
→ 성장·수확·기록·도감
→ MVP-1 검증
→ v2 판단
```

## 2. 단계별 계획

### Phase 0 — 안전한 초기화

Git과 Next.js TypeScript 프로젝트를 현재 폴더에 만들고 Node/pnpm 버전, lockfile, lint, typecheck, Vitest, Playwright, `.env.example`, README를 구성한다. 깨끗한 설치 후 개발 서버와 production build까지 확인한다.

### Phase 1 — AI보다 제품 규칙 먼저

목표, 행동, 진행 단위, cm, 생명주기 Zod 스키마를 정의한다. 유한성, 진행률, 성장 단계, 활성 목표 3개, 수확 자격을 순수 함수로 만들고 경계값 중심 표 기반 테스트를 작성한다. 순화된 한국어 문구도 상수화한다.

### Phase 2 — 목표 분석 수직 흐름

목표/맥락 폼과 서버 전용 AI endpoint를 만든다. 구조화 결과를 검증해 cm, 이유, 유한성, 진행 단위를 표시한다. `∞cm`는 초안을 보존한 채 시작 체크를 차단하고 API 실패에는 안전한 재시도와 기본 제안을 제공한다.

### Phase 3 — 3분 행동과 씨앗

추천 말풍선, 입력칸, 손가락 복사 버튼, 수정 행동 재검증, 60초 타이머를 구현한다. `시작했어요`에서만 씨앗을 한 번 생성하고 선택적 `마쳤어요`, 다시 준비, 다음 기회 흐름을 만든다.

### Phase 4 — Local-first 목표 관리

저장소 인터페이스와 IndexedDB adapter를 만든다. 초안부터 동결까지 상태를 복원하고 활성 목표 3개 제한과 동결창고를 구현한다. 스키마 버전과 손상 데이터 복구도 검증한다.

### Phase 5 — 진행률과 재방문

지원 진행 단위를 동일 비중으로 계산하고 사용자가 단위와 범위를 정정하게 한다. 비연속 누적 목표를 지원하고 활성 카드에 저장된 일반 추천 행동을 표시한다. 새 추천은 사용자 요청 시에만 생성한다.

### Phase 6 — 선택적 계정 연결

승인된 Supabase에 migration과 RLS를 만든다. 익명 사용자가 첫 행동을 지연시키지 않도록 생성 시점을 검증하고, 첫 씨앗 후 Google OAuth 계정 연결과 로컬 데이터 병합을 idempotent하게 구현한다. 다른 기기 복원과 사용자 간 격리를 테스트한다. 이메일 로그인은 MVP 사용자 요구가 확인될 때만 추가한다.

### Phase 7 — MVP-0 검증

모바일·데스크톱 E2E와 AI 오류, 타이머 이탈, 오프라인 로컬 사용, 무한 목표, 활성 목표 제한을 검증한다. 개인정보를 담지 않는 funnel/return 이벤트와 압박감 중심 사용성 테스트를 진행한다.

### Phase 8 — MVP-1 성장과 수확

고정 성장 시각, 100% 열매 준비, 큰 수확 CTA, 건너뛸 수 있는 애니메이션을 만든다. 버전이 있는 품종 자격과 고정 확률 추첨을 테스트하고 명시적 수확 기록을 한 번만 저장한다.

### Phase 9 — 기록장과 도감

기록 목록·상세, 획득/미획득 품종, 중복 수확 누적을 구현하고 로컬과 클라우드 복원을 검증한다.

### Phase 10 — MVP-1 출시 준비

문구, 접근성, 반응형, reduced-motion을 점검한다. 전체 테스트, AI 한국어 품질·지연·비용 평가, 배포·모니터링·백업·롤백 문서를 완료한다.

## 3. 최우선 테스트

- 허용 cm 외 값 거부
- `∞cm` 씨앗 차단
- 첫 행동이 최종 목표를 덮어쓰지 않음
- 시작 확인 시 씨앗 한 번만 생성
- 시간으로 성장하지 않음
- 누적 목표가 쉰 날 때문에 감소하지 않음
- 활성 목표 3개 초과 차단
- 동결 시 모든 상태 보존
- 100% 자동 수확 금지
- 목표당 중복 수확 금지
- 익명→계정 연결 시 기록 무손실
- 잘못된 AI 구조화 응답 거부

## 4. 사용자가 준비할 것

로컬 Phase 0~1을 시작하는 데 필요한 것은 없다. 실제 연동 직전에는 다음이 필요하다.

1. 새로 발급한 OpenAI API 키와 월 개발 예산. 대화에 노출된 키는 사용하지 않는다.
2. 실제 Supabase 프로젝트 URL과 publishable key. Supabase 사용 자체는 승인되었다.
3. Google OAuth용 Google Cloud client ID와 client secret
4. 배포 시 Vercel 계정/프로젝트. 그전까지 설정을 보류한다.

비밀키는 추적되는 문서나 Git에 넣지 않고 로컬 환경 변수 또는 호스팅 대시보드에만 입력한다.

기본 오렌지 이미지는 `public/images/orange-main.png`에 준비되어 있다.

## 5. 첫 구현 체크포인트

첫 코딩은 Phase 0과 Phase 1까지만 진행하고 멈춰 검토한다. 이때 실제 AI나 DB 연결 없이도 전체 제품 규칙이 실행 가능한 테스트로 고정되어 있어야 한다. 승인 후 Phase 2로 넘어간다.
