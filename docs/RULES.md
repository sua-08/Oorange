# Orange Task Farm — RULES

이 문서는 구현 중 임의로 바꾸면 안 되는 제품 규칙을 정의한다. 충돌 시 `RULES.md` → `PRD.md` → `IMPLEMENTATION_PLAN.md` → 코드 순서로 우선한다.

## 1. Product philosophy

1. 생산성보다 시작을 우선한다.
2. 완료보다 첫 행동을 더 중요하게 취급한다.
3. 경쟁, 실패, 죄책감, 연속 출석 압박을 만들지 않는다.
4. 모든 기능은 “사용자가 시작하기 쉬워지는가?”로 판단한다.

## 2. Goal and AI rules

1. 최종 목표와 3분 행동을 별도 데이터로 보존한다.
2. 목표 줄이기는 최종 목표를 축소하는 과정이 아니라 연결된 첫 행동을 찾는 과정이다.
3. 최종 목표는 유한한 완료 기준과 동일 비중 진행 단위를 가져야 한다.
4. 무한 목표는 `∞cm`로 표시하고 유한화 전에는 시작 확인과 씨앗 생성을 차단한다.
5. 활성 목표는 최대 3개이며 나머지는 불이익 없이 동결창고에 보관한다.
6. AI는 cm를 고정 단계에서만 고르고 이유를 설명한다.
7. AI는 진행 단위를 추천하되 사용자가 바꿀 수 있다.
8. AI는 제공되지 않은 목표 내용을 추측하지 않는다.
9. 씨앗 생성 전 사용자 수정 행동은 3분 기준을 다시 검증한다.
10. AI 응답은 서버에서 스키마 검증을 통과해야 한다.

허용 cm는 `0.5, 1, 2, 3, 5, 10, 20, 30, 50, 75, 100, 150, 200, 300, 500, 1000, infinity`뿐이다. 3분 행동은 원칙적으로 3cm 이하다. cm와 3분 가능 여부는 별도 필드다.

## 3. Start, progress, and growth rules

1. 1분 안에 시작했다고 확인한 순간 최종 목표에 연결된 씨앗을 한 번만 생성한다.
2. 작은 행동 완료는 요구하지 않으며 준비 행동도 유효하다.
3. `마쳤어요`는 선택적 축하이며 진행률을 올리지 않는다.
4. 시작하지 못해도 실패로 기록하지 않는다.
5. 성장은 최종 목표 진행률로만 계산한다. 시간은 성장량에 영향을 주지 않는다.
6. 진행 단위는 동일 비중이며 가중치를 사용하지 않는다.
7. 도전형 목표는 연속이 아닌 참여 횟수를 누적한다.
8. 수확 전 범위와 진행률 정정을 허용하고 불이익을 주지 않는다.
9. 성장 구간은 0%, 1~25%, 26~60%, 61~99%, 100%로 고정한다.

## 4. Harvest and rewards rules

1. 100%에서 자동 수확하지 않는다.
2. 사용자의 수확 버튼으로만 영구 기록과 품종 추첨을 만든다.
3. 수확한 오렌지는 영구 보관하며 소비하지 않는다.
4. 기본 품종 확률을 가장 높게 유지한다.
5. 특별 품종은 조건 충족 시 낮은 고정 확률로만 추첨한다.
6. 점진적 확률 보정, 결제 확률 상승, 광고 재시도는 금지한다.
7. 해금은 오렌지 소비가 아닌 누적 수확 조건을 사용한다.

## 5. UX language rules

- 지양: 실패, 포기, 퇴화, 시간 초과, 연속 기록 초기화, 뒤처짐
- 권장: 다음에 시작할게요, 한 번 더 준비할래요, 안전하게 쉬고 있어요, 진행 상태를 다시 맞췄어요
- 한 화면에는 하나의 핵심 행동을 우선한다.
- 애니메이션은 짧고 건너뛸 수 있어야 한다.
- 핵심 CTA는 장식에 가려지면 안 된다.

## 6. Account, raid, and scope rules

1. 로그인 없이 MVP Core Loop를 사용한다.
2. 계정 연결은 첫 씨앗 이후 선택적으로 제안하고 기존 기록을 보존한다.
3. MVP 로그인은 Google OAuth를 우선하며 이메일 로그인은 필요성이 검증된 뒤 추가한다.
4. 사용자별 클라우드 데이터는 서버 정책으로 격리한다.
5. v2 레이드는 선택적인 일일 주제별 참여 이벤트다.
6. 레이드에는 개인 순위, 기여도, 목표 인원, 공동 성공·실패가 없다.
7. MVP-0 → MVP-1 → v2 순서로 개발한다.
8. 완료된 작업만 TODO에 `[x]`로 표시한다.
9. 새 기능은 PRD 충돌 여부와 시작 장벽을 먼저 검토한다.
