# Orange Task Farm

큰 목표를 작은 시작으로 바꾸는 오렌지 할 일 측정소입니다.

현재 구현 범위는 여덟 번째 vertical slice의 독립 도감 화면까지입니다. 목표와 맥락을 입력하면 서버의 OpenAI 분석이 오렌지 크기, 판단 이유, 추천 첫 행동과 진행 단위를 보여줍니다. 결과에서 더 작은 행동을 골라 다시 측정할 수 있고, 3분 안에 마칠 수 있는 행동에 도달하면 1분 카운트다운을 시작할 수 있습니다. 시간 안에 실제로 시작했음을 확인하면 원래 최종 목표를 대표하는 씨앗을 얻습니다. 첫 행동은 최종 목표와 별도로 유지됩니다.

완료 기준이 없는 목표는 ∞cm로 표시하고 유한한 목표로 다시 측정하기 전에는 씨앗을 얻을 수 없습니다. 목표·첫 행동·씨앗은 현재 브라우저의 IndexedDB에 저장되어 새로고침 후 복원됩니다. 활성 목표는 최대 3개이며 동결창고로 잠시 보관하거나 다시 활성화할 수 있습니다. 브라우저 데이터를 지우면 복구할 수 없으며, Supabase·계정 동기화는 아직 연결되지 않았습니다. 1분 타이머 자체는 새로고침 후 재시작해야 합니다.

씨앗을 얻은 뒤에는 최종 목표의 진행 단위·전체 범위·현재량을 직접 설정하고 정정할 수 있습니다. 참여 일수도 연속 기록이 아닌 누적량입니다. 진행률에 따라 씨앗·새싹·나무·꽃·열매 준비 상태를 표시합니다. 실제 완료량이 전체와 같을 때만 큰 `수확하기` 버튼이 나타납니다. 버튼을 눌러야 품종이 한 번 추첨되고 기록장에 보관됩니다. 같은 목표는 다시 수확할 수 없습니다. 기존 브라우저 저장 데이터는 진행률·수확 항목이 없어도 그대로 읽습니다. `/encyclopedia`에서 품종별 수확 수와 발견 여부를 볼 수 있습니다. 같은 품종을 여러 목표에서 수확하면 횟수가 누적됩니다.

활성 목표 카드에는 저장된 추천 행동을 표시합니다. 추천을 입력칸에 복사해 수정할 수 있고, 새 추천은 `다른 행동 추천받기`를 누를 때만 요청합니다. 이 단계에서는 타이머나 완료 확인을 요구하지 않고 진행률도 자동으로 바꾸지 않습니다.

품종 규칙 v1: 기본 오렌지 94%, 햇살 오렌지 6%. 수확 가능한 완료 목표에서만 추첨하며 확률 보정·재추첨은 없습니다. 이 확률은 임시 제품 설정이며 코드에 버전과 함께 기록됩니다. 수확 기록도 현재는 이 브라우저에만 있으므로 브라우저 데이터를 지우면 복구할 수 없습니다.

## 실행

```bash
pnpm install
pnpm dev
```

브라우저에서 `http://localhost:3000`을 엽니다.

## 검사

```bash
pnpm lint
pnpm typecheck
pnpm test
pnpm build
```

## 환경 변수

프로젝트 루트의 `.env.local`에 `OPENAI_API_KEY=` 뒤로 본인의 새 API 키를 직접 입력한 다음 개발 서버를 다시 시작하세요. 키를 채팅이나 코드에 붙여넣지 마세요. `.env.local`은 Git에서 제외되며 `.env.example`에는 빈 이름만 둡니다. 키가 없으면 화면에 연결 준비 안내가 표시됩니다.

자동 테스트는 실제 API를 호출하지 않습니다. 실제 연동 수동 점검은 키와 사용 한도를 설정한 뒤 브라우저에서 `게임 만들기`, `강의 5개 듣기`, `책 한 권 읽기`, `운동하기`를 각각 입력해 측정·축소·씨앗 흐름과 무한 목표 차단을 확인하세요. 씨앗을 얻은 뒤 진행 단위와 전체 범위를 정하고 `+1` 기록, 정정, 새로고침 복원을 확인하세요. 100%에서는 수확 전 기록장이 비어 있는지, `수확하기`를 누른 뒤 결과와 기록장 항목이 하나만 생기는지, 새로고침 뒤에도 남는지 확인하세요.
